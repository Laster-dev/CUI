## 2. P1 — 会造成实际损害的问题

| # | 问题 | 后果 | 建议 |
|---|---|---|---|
| 1 | `open()` 缺少 `newline=''` | Windows 上写入时把 CRLF 改写为 LF，**污染整个仓库换行**，产生海量无意义 diff | 所有文本读写显式指定 `newline=''`（读取保留原样）或 `newline='\r\n'`（写入） |
| 2 | 硬编码绝对路径 `E:\C++project\CUI\` | 换机器/换盘符后脚本全部失效 | 以脚本文件位置向上推导仓库根：`Path(__file__).resolve().parents[1]` |
| 3 | 无备份 | 批量改写源码出错后无法恢复 | 写入前复制 `.bak`，或要求工作区干净（git）并在失败时 `git checkout` |
| 4 | 非幂等 | 重复执行会重复插入同一段代码/条目 | 改为"检测—替换"或加锚点标记，重复执行结果不变 |
| 5 | 缺少异常处理与整体事务 | 中途失败留下半改状态 | `try/except` + 先全部生成到内存、校验通过后再统一落盘 |

---

## 3. P2 — 工程质量

- 无统一入口/参数约定：建议加 `scripts/_common.py`（路径解析、读写封装、日志、备份、干跑 `--dry-run`）。
- 无 `--dry-run` 模式：批量修改类脚本应默认干跑，确认后再 `--apply`。
- 编码未显式声明：`open(..., encoding='utf-8')`；部分脚本可能还涉及 GBK 文件，需统一探测策略。
- 缺少说明：`scripts/` 下应有一份 README，说明每个脚本用途、用法、是否破坏性。
- 建议接入 CI 做一次静态检查（`ruff` / `flake8`）与"换行一致性"检查。
