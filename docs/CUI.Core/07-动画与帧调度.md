# 07 · 动画与帧调度

## 一、四个类的分工

| 类 | 文件 | 作用域 | 职责 |
|---|---|---|---|
| `AnimationService` | `animation/AnimationService.h` | 进程级单例 `Instance()` | 算法库（缓动/指数逼近/Spring）+ **集中 Tick**：遍历所有注册元素调用 `OnAnimationTick()` |
| `AnimationManager` | `animation/AnimationManager.h` | 每窗口 `Current()` | 帧泵：维护"正在动画的元素"集合、`RequestWake` 定时唤醒、Live-Tree 门 |
| `FrameScheduler` | `animation/FrameScheduler.h` | 每窗口 `Current()` | 时钟：`ScheduleFrame()` 请求下一帧、计算距下一帧的毫秒数 |
| `AnimationSystem` | `animation/AnimationSystem.h` | 工具类 | `AnimatedScalar`（标量平滑器）+ `AnimationSpec`（参数） |

> 帧的驱动源是**窗口消息泵**（`Window::RunMessageLoop`），不是独立定时器。
> 想让下一帧发生 → `FrameScheduler::Current()->ScheduleFrame()`。
> （`InvalidateMeasure()` / `InvalidateArrange()` 内部已自动请求排帧，别重复排。）

## 二、参数：`AnimationSpec`

```cpp
struct AnimationSpec {                       // AnimationService.h:38
    float responseAt60Hz      = 0.20f;       // 响应速度（越小越"跟手"）
    float epsilon             = 0.01f;       // 收敛阈值，小于它认为到位
    float maxDurationSeconds  = 0.0f;        // 0 = 无固定时长（指数逼近收敛）；>0 = 固定时长，超时吸附到目标
    EasingType easing         = EasingType::EaseOutCubic;
};
```

## 三、缓动：`EasingType`（15 个）

`Linear`、`EaseInQuad`、`EaseOutQuad`、`EaseInOutQuad`、`EaseInCubic`、`EaseOutCubic`、`EaseInOutCubic`、`EaseInExpo`、`EaseOutExpo`、`EaseInOutExpo`、`EaseInBack`、`EaseOutBack`、`EaseInOutBack`、`EaseOutBounce`、`Spring`

默认 `EaseOutCubic`（Fluent UI / CSS 推荐标准）。

## 四、标量平滑：`AnimatedScalar`

```cpp
AnimatedScalar(float value = 0.0f);          // AnimationSystem.h:34
void SetTarget(float value);
bool Tick(float dtSeconds, const AnimationSpec& spec);   // :54 返回是否仍在动画中
```

典型用法（在 `OnAnimationTick` 里）：

```cpp
bool MyWidget::OnAnimationTick() {
    float dt = AnimationService::Instance().GetDeltaSeconds();
    bool running = m_anim.Tick(dt, m_spec);
    MarkRenderContentDirty();      // 别忘了标脏，否则不重绘
    return running;                // 返回 false → 自动注销，停止吃帧
}
```

## 五、UIElement 的动画契约

| 成员 | 说明 |
|---|---|
| `virtual bool OnAnimationTick()` | 每帧被调用；**返回 false 自动注销** |
| `virtual bool HasSelfAnimation() const` | 声明自己是否有活动动画（影响脏区收集） |
| `virtual bool IsComposeOnlyAnimation() const` | true = 只走 DComp 合成，不需要重绘 |
| `virtual bool ComposePresent(GraphicsContext&)` | 硬件合成呈现入口 |
| `virtual void CollectSelfAnimationBounds(Rect& dirty, bool& hasDirty)` | 上报自身动画脏矩形 |
| `virtual void CollectAnimationBounds(Rect& dirty, bool& hasDirty)` | 递归上报含子树的动画脏矩形 |

注册/注销（在 `AnimationService` 上）：

```cpp
AnimationService::Instance().RequestAnimationTicks(this);   // 开始吃帧
AnimationService::Instance().CancelAnimationTicks(this);    // 停止
AnimationService::Instance().RegisterElement(this);         // 仅登记到服务
AnimationService::Instance().UnregisterElement(this);
AnimationService::Instance().SetAnimationsEnabled(false);   // 全局开关（无障碍/省电）
float dt = AnimationService::Instance().GetDeltaSeconds();  // dt 已被 clamp 到 [1/240, 0.05]
```

> 元素析构时会自动注销并取消唤醒，**不需要**手动清理。

## 六、帧调度与唤醒

```cpp
// FrameScheduler（每窗口）
FrameScheduler::Current()->ScheduleFrame();                  // 请求下一帧
FrameScheduler::Current()->ScheduleFrameAt(when);            // 指定时刻
FrameScheduler::Current()->CancelScheduled();
FrameScheduler::Current()->SetMinFrameInterval(duration);    // 限帧
int ms = FrameScheduler::Current()->GetMsUntilDeadline(now); // 供消息泵计算等待时长

// AnimationManager（每窗口）
AnimationManager::Current()->RequestFrame();                 // 标记需要一帧
AnimationManager::Current()->RequestWake(this, when);        // 定时唤醒某元素
AnimationManager::Current()->CancelWake(this);
AnimationManager::Current()->RegisterAnimating(this);        // 加入动画集合
AnimationManager::Current()->UnregisterAnimating(this);
AnimationManager::Current()->SetLiveRoot(root);              // Live-Tree 门
AnimationManager::Current()->SetTargetFrameSeconds(1.0f/60); // 目标帧长
bool ticked = AnimationManager::Current()->Tick();
```

## 七、Live-Tree 门（重点）

`AnimationManager::SetLiveRoot(root)` 设定"当前活跃子树"。**不在 Live 树上的元素不会被 Tick**——这是页面切走（如 NavigationView 切换）后动画自动停转的机制。

排查"动画莫名其妙不动"时，先看：

1. 元素是否还在 Live 树里（`GetLiveRoot()`）
2. 有没有真的 `RequestAnimationTicks(this)` / `RegisterAnimating(this)`
3. `OnAnimationTick()` 是不是第一帧就返回了 `false`
4. 有没有 `MarkRenderContentDirty()`（不标脏 = 值在变但屏幕不变）

## 八、Control 自带的过渡动画

`Control`（`controls/Control.h`）已经内置 Hover / Pressed / Focused 的视觉状态过渡。自定义控件若继承 `Control`，通常**不需要**自己写这些动画，只要：

- 用 `HoverBackgroundToken` / `PressedBackgroundToken` 等 Token 让框架取色
- 需要状态变化时写 `HasSelfAnimation()` 返回 true

## 九、性能建议

- 能用 DComp 合成的（位移/透明度/缩放）走 `IsComposeOnlyAnimation() == true`，避免 CPU 重绘。
- 动画只标脏它真实覆盖的矩形（`MarkRenderRectDirty`），别整控件标脏。
- 收敛后立即返回 `false` 注销，别让空转动画常驻。
- 批量静止时用 `SetAnimationsEnabled(false)` 降低功耗。
