# 10 · 规约与已知陷阱

## 一、命名规范

| 对象 | 风格 | 示例 |
|---|---|---|
| 类 / 结构体 | PascalCase | `NavigationViewItem` |
| 控件公开属性成员 | PascalCase | `Text`、`CornerRadius`、`SelectedIndex` |
| 私有成员 | `m_` + camelCase | `m_dpiScale`、`m_measureDirty` |
| 方法 | PascalCase | `InvalidateMeasure()`、`SetRootElement()` |
| DSL 链式方法 | PascalCase | `.FontSize(24)` |
| 自由函数（DSL 工厂） | PascalCase + `Widget` 后缀（约定） | `SliderWidget()`、`GridWidget()` |
| 文件 | 与类名同名 | `NavigationView.h` / `.cpp` |
| 命名空间 | `CUI`，DSL 在 `CUI::DSL` | |

## 二、包含规范

- 附加包含目录根是 `CUI.Core/ui`，所以一律写 `"framework/xxx/yyy.h"`。
- 应用工程只需 `#include "CUI.h"`（伞形头，`ui/CUI.h`）。
- 库内部互引用用相对路径（如 `"../render/GraphicsContext.h"`）。
- 每个头文件都有 `#pragma once`。
- 平台头（`windows.h`、`d2d1.h`）由框架头内部引入，不要在应用代码里重复配置宏。

## 三、内存与生命周期

- 子节点用 `std::shared_ptr<UIElement>`（别名 `Element`）持有；`GetParent()` 是**不拥有所有权**的裸指针。
- 跨回调/跨帧保存元素 → `std::weak_ptr`（框架内部用 `CaptureElementRef()` 提升后使用，避免 UAF）。
- `~UIElement()` 会自动：解绑文本绑定、从 `AnimationService` 注销、取消 Tick、取消唤醒、断开子节点父指针。**不会**在析构期触发 render dirty。
- 不要把 `this` 裸指针塞进异步任务；用 `weak_ptr` 并在使用时 `lock()`。

## 四、线程模型

- **单 UI 线程**：所有元素树操作、布局、绘制都在创建窗口的那个线程。
- 工作线程要更新 UI → 投递回 UI 线程（自定义消息 / 任务队列）再改元素。
- `AnimationService::Instance()` 是进程级单例；`AnimationManager::Current()` / `FrameScheduler::Current()` / `Window::Current()` 是每窗口上下文，**换窗口会变**。

## 五、编码与字符集

- 源码 UTF-8，编译 `/utf-8`，工程为 Unicode。
- 传给 Win32 的字符串需转 UTF-16（`Window::Create` 内部已处理，自己调 Win32 API 时要自己转）。
- 控件文本接口统一 `std::string`（UTF-8）。

## 六、代码风格

- Allman 花括号（独占一行）。
- 中文行末注释解释"为什么"，格式为 `// 说明`。
- 公开方法都带 `///` 或块注释说明参数与返回值（现有代码惯例）。
- 优先 `if constexpr (requires { ... })` 做能力检测（DSL 方法就是这样支持跨控件复用的）。

## 七、已知陷阱（照着排查能省半天）

| 陷阱 | 症状 | 对策 |
|---|---|---|
| **DSL 静默降级** | 链式方法编译通过但无效 | `if constexpr (requires{...})` 不满足时静默跳过；不确定就直接调控件 setter |
| **忘记加 vcxproj** | `LNK2019` | 新 `.cpp` 手工写进 `CUI.Core.vcxproj`（无通配符） |
| **物理像素当 DIP** | 高分屏错位、线宽异常 | 只有 `Resize` / `EndDraw(RECT*)` / `EnsureCompositionSurface` 用像素；Win32 鼠标坐标先 `ClientPhysicalToLogical()` |
| **没有 `InvalidateVisual()`** | 找不到失效 API | 用 `InvalidateMeasure()` / `InvalidateArrange()` / `MarkRenderContentDirty()` |
| **Push/Pop 不配对** | 绘制错位、整屏消失 | Clip / Opacity / Transform / Layer 必须成对 |
| **Builder 悬垂引用** | 随机崩溃 | `ElementBuilder<T>& r = X().Width(1);` 错；用 `auto b = ...;` |
| **动画空转** | CPU 常驻占用 | `OnAnimationTick()` 收敛后返回 `false`；不在 Live 树的元素自动停 |
| **改了不重绘** | 数据变了画面没变 | 补 `MarkRenderContentDirty()`（或在动画里每帧标脏） |
| **Grid 星号列不回缩** | 窗口变窄布局异常 | 已知问题，见 `docs/review/07` 与 `layout/Layout.cpp` 星号分配段 |
| **工具集漂移** | 换平台编译失败 | x64 用 v143、Win32 用 v145（工程未统一） |
| **NuGet 未还原** | 构建一开始就被打断 | `VC-LTL.5.3.1` 必须先还原 |

## 八、调试技巧

- `Window::Fluent().RenderStats(true)` 打开渲染统计浮层（帧率、绘制耗时）。
- `UIElement::GetLayoutGeneration()` 递增说明真的重排过。
- 布局问题：在 `MeasureOverride` 打印 `availableSize` 与子节点 `DesiredSize`。
- 绘制问题：先用 `FillRect` 画满控件确认 `GetBounds()` 是否符合预期，再排查细节。
