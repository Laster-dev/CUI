## 三、三条不变量（破坏它们 = 必出诡异 Bug）

### 1. 坐标单位是 DIP

布局、`Rect`/`Point`/`Size`、线宽、圆角、字号**全部是 DIP**。物理像素只出现在：

| API | 单位 |
|---|---|
| `GraphicsContext::Resize(UINT w, UINT h)` | 物理像素（交换链缓冲区） |
| `GraphicsContext::EndDraw(const RECT* dirtyRectPx)` | 物理像素（传 `nullptr` = 全量） |
| `GraphicsContext::EnsureCompositionSurface(..., UINT wPx, UINT hPx)` | 物理像素（DComp 表面） |

换算：`m_dpiScale = GetDpiForWindow(hwnd) / 96.0f`；`d2dContext->SetDpi(dpiX, dpiY)` 之后 1 DIP = dpi/96 物理像素。
Win32 消息的鼠标坐标是物理像素 → `ClientPhysicalToLogical()` 后才能用于命中测试。

### 2. 元素树：子用 `shared_ptr`，父是裸指针

```cpp
void AddChild(std::shared_ptr<UIElement> child);   // 强引用
UIElement* GetParent() const;                      // 弱引用，不拥有所有权
using Element = std::shared_ptr<UIElement>;        // UIElement.h
```

- 跨帧/跨回调保存元素 → 用 `std::weak_ptr`（框架内部即 `CaptureElementRef()` 做提升，防止 UAF）。
- `~UIElement()` 会把所有子节点的 `parent` 置空再 `clear()`，**不会**在析构期触发 render dirty。
- 析构自动完成：解绑文本绑定、从动画服务注销、取消 Tick、取消唤醒、断开子节点的父指针。

### 3. 改了必须显式失效

| 你改了什么 | 调哪个 |
|---|---|
| 影响自身或子树尺寸的内容 | `InvalidateMeasure()`（连带置 Arrange 脏并向上冒泡） |
| 只影响位置 | `InvalidateArrange()` |
| 只影响外观 | `MarkRenderContentDirty()` 或 `MarkRenderRectDirty(rect)` |
| 树结构变化 | `NotifyVisualTreeChanged()`（由 `AddChild` 等内部调用） |

> ⚠️ 框架**没有** `InvalidateVisual()`。找不到就说明该用上面三个之一。

## 四、一帧发生了什么

```
Window::RunMessageLoop()                          // window/Window.cpp
  ├─ PeekMessage 排空输入类消息（键盘/鼠标/IME，预算 100 条）
  │    · WM_MOUSEMOVE 只保留最新一条（合并）
  │    · DispatchRoutedPointer() → UIElement::OnRoutedEvent(args)
  │      或落到经典虚函数 OnMouseDown / OnKeyDown …
  ├─ 取一条普通消息（WM_QUIT → return）
  ├─ 为每个窗口设置"当前上下文"：
  │    Window::s_current / AnimationManager / FrameScheduler / PopupHost / DragDropService
  ├─ AnimationService::Instance().Tick(now)
  │    · 计算 dt（clamp 到约 [1/240, 0.05] 秒）
  │    · 遍历已注册元素 → UIElement::OnAnimationTick()（返回 false 者移除）
  ├─ PumpFrameStep(now)
  │    ├─ 脏则 Measure(available) → LayoutEngine::MeasureElement → MeasureOverride
  │    ├─ Arrange(rect) → 扣 Margin → LayoutEngine::ArrangeElement → ArrangeOverride
  │    ├─ SyncRenderState()
  │    └─ Render(ctx) → OnRender(ctx) → 递归子节点 → RenderOverlay
  └─ EndDraw(dirtyRectPx?) / CommitComposition()
```

要点：

- **帧的驱动源是消息泵**，不是定时器；需要动画时用 `FrameScheduler::ScheduleFrame()` 请求下一帧。
- `InvalidateMeasure()` 内部就会请求排帧，所以改属性后不必手动排帧。
- 渲染顺序：`Render()`（基类管 Opacity / Clip / 层缓存）→ `OnRender()`（你重写）→ 递归 `GetVisualChildren()` → `RenderOverlay()`。

## 五、全局单例 / 当前上下文

| 单例 | 获取方式 | 作用域 |
|---|---|---|
| `AnimationService` | `AnimationService::Instance()` | 进程级（算法库 + 集中 Tick） |
| `AnimationManager` | `AnimationManager::Current()` | **每窗口**，消息泵里 `SetCurrent` |
| `FrameScheduler` | `FrameScheduler::Current()` | 每窗口 |
| `ThemeManager` | `ThemeManager::Instance()` | 进程级 |
| `Window` | `Window::Current()` | 每窗口 |
| `DragDropService` | `DragDropService::Current()` | 每窗口（等价 `Window::GetDragDrop()`） |
| `PopupHost` | `Window::GetPopupHost()` | 每窗口 |

> 结论：跨窗口/跨线程调用 API 前，先确认目标单例是"进程级"还是"当前窗口级"。

## 六、关键基类速记

| 类 | 文件 | 你要知道的事 |
|---|---|---|
| `Object` | `core/Object.h`（22 行） | 只有 `virtual ~Object()`；`TypeName()` 是宏注释占位（真正有实现的是 `utils/TypeName_decl.h` 的 `StaticTypeName<T>()`） |
| `UIElement` | `controls/UIElement.h`（686 行） | 树 + 属性 + 布局 + 命中 + 渲染 + 动画 + 拖拽 + 路由 |
| `Control` | `controls/Control.h` | 在 `UIElement` 之上加 Hover / Pressed / Focused 视觉状态与过渡动画 |
| `GraphicsContext` | `render/GraphicsContext.h`（1048 行） | 唯一的绘制入口，`OnRender(ctx)` 的参数 |
| `LayoutEngine` | `layout/Layout.h` | 静态函数集合，非 OO；由 `UIElement::Measure/Arrange` 分发 |

**选择继承谁**：纯展示 → `UIElement`；可交互 → `Control`；容器 → `Panel`（`controls/panels/`）并重写 `MeasureOverride` / `ArrangeOverride`。
