# Canvas 坐标刷新与 ZIndex 设计

## 目标

修复 Gallery Canvas 页面中“随机重排”点击后圆形不移动的问题，并提供正式、可扩展的显式层级控制。修复后，Canvas 子元素的坐标变更必须立即反映到布局、绘制和命中测试；叠加示例必须稳定且清晰地展示图层关系。

## 范围

- 修正 `Canvas.Left`、`Canvas.Top`、`Canvas.Right`、`Canvas.Bottom` 更新后的布局与重绘失效流程。
- 新增 `ZIndex` 附加属性，并使其影响 Canvas 子元素的绘制与命中顺序。
- 更新 Canvas Gallery 示例，使其使用明确的位置、层级和可见的重叠构图。
- 保持现有未设置 `ZIndex` 的界面兼容。

不在本次范围内：为非 Canvas 容器新增独立的视觉树重排 API，或改变现有覆盖层（Overlay）合成规则。

## 行为定义

### 坐标更新

1. 子元素的任一 Canvas 定位属性变更后，元素和父级 Canvas 必须进入 Arrange 失效状态。
2. 下一帧布局刷新时，Canvas 按新定位属性重新计算该子元素的边界。
3. 旧边界和新边界都必须被标记为需要重绘，防止移动后出现残影。
4. Gallery 的随机重排应在画布可用范围内生成新位置，并避免生成与当前位置相同的位置；状态文字应显示新的整数坐标。

### 层级

1. 每个 `UIElement` 均拥有整数 `ZIndex`，默认值为 `0`。
2. Canvas 的绘制顺序按 `(ZIndex, AddChild 顺序)` 升序：较小值先绘制，较大值后绘制并显示在上方。
3. 相同 `ZIndex` 保持现有 `AddChild` 稳定顺序，以确保未使用 `ZIndex` 的界面行为不变。
4. 命中测试使用上述顺序的反向遍历，因此更高 `ZIndex` 优先接收输入；同级时后添加者优先。

## 实现边界

- 在现有属性桥接中注册并通知 `ZIndex`，其变更应使父级重绘；当父容器为 Canvas 时还应更新层级排序结果。
- Canvas 的布局只负责定位，绘制和命中测试在 UI 树遍历时使用同一稳定排序规则，避免视觉层级与输入层级分叉。
- 排序不得改变 `m_children` 的存储顺序；使用稳定的临时遍历顺序，避免影响树生命周期、绑定和默认兼容性。
- 仅在 Canvas 页示例显式调用 `SetZIndex`，用蓝色矩形 `0`、橙色椭圆 `1`、红色斜线 `2` 展示叠加关系。

## 验收标准

- 连续点击“随机重排”时，圆形每次都在 Canvas 边界内移动，画面无残影，坐标文本随之变化。
- 叠加示例中可同时看见蓝色矩形、橙色椭圆和红色斜线的交叠部分。
- 红线位于最上层；点击重叠区域时，命中对象与最高 `ZIndex` 一致。
- 未设置 `ZIndex` 的 Canvas 子元素继续按原始 `AddChild` 顺序绘制，且命中顺序保持“后添加优先”。

## 验证

- 编译 `CUI.Gallery` 目标。
- 手动打开 Canvas 页面，验证重排、层级显示和重叠区域命中。
- 如项目已有适合的布局/控件单元测试入口，则补充或运行覆盖 Canvas 定位及层级排序的最小测试。
